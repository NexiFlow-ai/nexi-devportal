NexGraph

Add a source

Upload a quarterly report and a transport agreement into the Project, see the three kinds of source NexGraph reads from, the five states every binding carries, its documents, and what Revoke does and does not do. About fifteen minutes.

For: builder, memberRequires: Project owner or editor to add, pause, resume or revoke a source; any member to read the list, the states and the documentsLast verified against the application: 2026-09-23

Goal

A Project's knowledge starts with a source — a place NexGraph is allowed to read from. This chapter adds two documents by upload, shows the two continuous kinds (a server folder and a Google Drive folder) so you know what they ask for, and reads the binding the upload created: its five states, the documents behind it and the one operation an upload binding has.

The idea underneath: NexGraph defines the scope, Synapse connects, NexCore checks rights — the first line of the wizard. A source is bound to one Project and inherits that Project's classification; the pipeline reads it with the rights of the Project, never with yours; and the documents it produces are visible to whoever holds a relation to the Project, exactly as far as that relation reaches.

Who can do this

RoleCanCannot
Project owner or editorAdd a source of any kind; upload documents into an Upload binding; pause, resume and revoke; open every document and run.Add a source to a Project they are not an editor of; widen the scope of a source beyond its Project; edit or verify the base tier.
Any member (viewer)Read the Sources list, a binding’s five states, its documents and its sync record; open the documents.Add, pause, resume or revoke. The buttons are disabled with the reason “Requires binding.create”.
Organization administrator without a Project relationSee the operational view: bindings, grants, budgets and run health.See document names, counts of knowledge or content — “Administering is not reading.”
An agent or a serviceRead within the Projects of the person it acts for.Create a binding, upload, or operate a source — SERVICE_NOT_ALLOWED.

Before you start

  • A Project you own or edit. We use Data science, which every organization gets from the Nexi Base blueprint.

  • Two files. Ours:

    acme-q3-2026-delivery-report.md — a one-page report whose table becomes claims in the next chapters:

northwind-framework-agreement-2027.pdf — a two-page contract between Acme Logistics B.V. and Northwind Traders GmbH: parties, a 24-month term, a rates table with four lanes, a 95 % on-time service level, payment terms. Any PDF with names, dates and a table will do.

  • Formats NexGraph reads: PDF; Word, RTF, OpenDocument text, EPUB; PowerPoint and OpenDocument slides; Excel, OpenDocument sheets, CSV; plain text, Markdown, MDX, HTML, AsciiDoc, LaTeX, JSON, XML; e-mail (.eml, .msg), calendar (.ics); PNG, JPEG, TIFF, WebP, BMP images. Up to 50 MB per file (the operator may set another limit).

Steps

1. Open Sources and read what is already there

In NexGraph, Knowledge → Sources.

You should see:

Knowledge sources — 2 sources · 1 managed · 1 base · 0 need attention. Two rows even in a fresh Project: Uploads (Upload · Project) — the box every upload lands in — and Nexi documentation (Base): the platform's own documentation, provided read-only to every organization so that questions about Nexi itself can be answered from the graph. Each row shows Sync (Current), Processing (Queued — nothing is running), Access (ACL current), the number of Documents and when it was Updated. Top right: Add source.

2. Add source — the three kinds

Press Add source.

You should see:

Add knowledge source with the sentence that governs it: NexGraph defines the scope. Synapse connects. NexCore checks rights. Four radio cards:

KindWhat it readsMode
Upload — Files you upload nowOne file per upload, into the Project's upload box.One-time
Server folder — A read-only folder on an approved server root, synced every minuteA path under a root the operator approved for this deployment.Continuous
Google Drive — A folder in your Google Drive, read through your own Google connection, synced every minuteA Drive folder and everything under it, through the Google connection you authorised in NexCore.Continuous
Gmail — Arrives with Synapse connectionsNot yet available; the card is disabled.—

With Upload selected: Choose file… or drop a file here · up to 50.0 MB, Document language (Detect by default), and the review facts every kind shows before you commit — Project Data science · Knowledge area Project — source rights kept · Mode One-time · Verification Subject → oracle / human gate. The last line is the promise of the whole product: whatever comes out of this source is a Subject proposal until an oracle or a person decides. The checkbox I reviewed the scope and mode. must be ticked before Add source → becomes available.

Choose Server folder to see what a continuous source asks for.

You should see:

Name, Approved root (a list the operator maintains — here shared), Path under the approved root with the hint Relative to the root. Hidden entries, secrets, symlinks and unsupported types are skipped; files larger than the limit too. Nothing is written to the folder. The facts now read Mode · Continuous and repeat the resolved path. The checkbox is stricter: I reviewed the root, the path and that the folder syncs continuously. A path that leaves the root (.., hidden segments) is refused before anything is saved.

Choose Google Drive.

You should see:

Name, then Allowed connection: Google Workspace is not connected with a Connect Google Drive button (a popup asks Google for drive.readonly only). The note explains the design: The worker reads the folder through your Google connection — NexCore holds the token, the browser and graph-api never see it. Then Drive folder — paste the folder link or its id — with the hint that Google Docs, Sheets and Slides are exported (DOCX · XLSX · PDF), unsupported types and files over the limit are skipped, nothing is written to Drive, and files shared with you count too. Until the connection is allowed and a folder is named, Add source stays disabled.

Back to Upload.

3. Upload the agreement

Choose northwind-framework-agreement-2027.pdf, tick the checkbox.

You should see:

The drop zone now reads northwind-framework-agreement-2027.pdf · 65.1 KB, the box is ticked and Add source → has turned black. Press it. The button reads Uploading… for a moment, the dialog closes, and the Uploads row shows one more document. Repeat for acme-q3-2026-delivery-report.md.

What happened: the bytes were stored once as a source version (Bronze) identified by their SHA-256 — uploading the same file again creates no second version — and a pipeline run was queued for it. The next chapter follows that run. If you only want to add documents to an existing Upload binding, the Inspector's Add document button (step 4) opens the same form with Upload preselected.

4. Read the binding — five states

Click the Uploads row.

You should see:

The Inspector: Uploads · Upload · Project · confidential, the button Add document, and the tabs Overview · Documents · 2 · Access. Under Five states every binding is described the same way, whichever kind it is:

StateHereWhat else it can say
ConnectionHealthyNeeds re-authorization (Drive token expired), Broken, Not applicable, Unavailable
ReachabilityReachableUnreachable (folder not mounted), Collector off, Not checked yet
ContentCurrentBehind (files changed, sync pending), Starting, Pinned, Unknown
Access (ACL)ACL currentChanged — serving blocked (Drive sharing changed; nothing is served until the pipeline re-checks), Unconfirmed, Public, …
ProcessingQueuedRunning, Behind, Failed, Paused, Idle

Then the facts: Mode One-time · Profile nexus://graph/scope/prf_default (the processing profile — which parsers, extractors and embedding model the pipeline uses) · Documents 2 · Content lag 0 s · Updated. Under Operations a single red-outlined Revoke, with the sentence that tells you what it means for this kind: An upload binding has nothing to pause. Revoking closes it: later uploads open a new one; documents stay.

A continuous binding shows more here: a Sync section (Last sync · Result · Files: n seen · new or changed · missing · settling · Next sync · Permissions), Pause and Resume beside Revoke (Pausing stops the sync and new runs; a running job finishes. Revoking stops for good and deletes nothing.), and when something is wrong, a next action in plain words — The folder is not reachable from the worker. Check the mount and the path, then wait for the next sync. or Re-authorize the connection to resume. with a Re-authorize button.

5. The documents behind it

Open the Documents · 2 tab.

You should see:

Two links: acme-q3-2026-delivery-report.md · v1 · 1.3 KB · 1 p and northwind-framework-agreement-2027.pdf · v1 · 65.1 KB · 2 p, each with its time. v1 is the source version; a re-upload of a changed file would add a v2 beside it and mark v1 superseded — nothing is overwritten. Each link opens the document in the Evidence Workspace. The Access tab lists who may read this source and why — your own Project relation, in plain words.

6. The same list across all your Projects

Open the switcher and choose All knowledge.

You should see:

The list gains a Project column: every binding of every Project you hold a relation to, and the base Nexi documentation once. Add source still names one Project — you add to a Project, never to "all".

Check

  • Sources shows Uploads · 2 documents and the pipeline queued or completed two runs (Overview → Runs · 24 h).
  • The Inspector's Documents tab lists both files as v1.
  • Uploading the report a second time changes nothing: same version, no new run.

What happens underneath

An upload is POST /graph/projects/{project}/uploads (multipart; the file and an optional language) into the Project's upload binding. graph-api checks the Project relation and the action binding.create at its enforcement point, sniffs the media type from the bytes (a renamed file is refused as unsupported), refuses anything over the limit before it is stored, then writes the bytes to the Bronze object store, records a SourceVersion whose identity is the SHA-256, emits source.version.created and places a pipeline order the worker picks up. A server folder or Drive binding does the same on every sync for each new or changed file — the worker lists the folder (through NexCore's content door for Drive, so the worker never holds a token), pins the bytes, and any file whose sharing changed is marked ACL changed — serving blocked until the pipeline has re-read it.

Nothing is deleted by Revoke: the binding stops syncing and running, the documents and everything derived from them stay with a revoked source mark on their provenance.

If something looks different

What you seeWhyWhat to do
“Add source” is disabled and its tooltip reads “Requires binding.create”.You are a viewer of this Project, or an organization administrator without a Project relation.Ask a Project owner to make you an editor. (On a brand-new organization the button may stay disabled until the Project holds its first binding — open the wizard from Overview → Add source, or from Review → “Upload a document with a table”.)
“This file type is not supported.”The bytes are not one of the formats above — the check is on content, not on the extension.Export the document as PDF, DOCX or plain text and upload that.
“The file is larger than 50.0 MB.”The deployment’s per-file limit.Split the document, or ask the operator whether a higher UPLOAD_MAX_ITEM_BYTES is acceptable.
“No approved root on this deployment” under Server folder.The operator has not approved any server folder root (SERVER_FOLDER_ROOTS).Use Upload or Google Drive, or ask the operator to approve a root.
Google Drive: “Connected as … — the connection expired” and the binding says Needs re-authorization.Google revoked or expired the token NexCore holds for you.Press Re-authorize in the binding’s Inspector (or Allow Drive access in the wizard). Sync resumes on its own.

Related API

Bindings: GET / POST /graph/projects/{project_id}/bindings (createBinding with kind ∈ upload · server_folder · google_drive, mode, scope_roots, connection_ref), GET /graph/projects/{project_id}/bindings/{binding_id}, POST …/pause · …/resume · …/revoke. Uploads: POST /graph/projects/{project_id}/uploads (uploadSource, multipart, 201 with the SourceVersion; 413 too large, 415 unsupported), GET /graph/projects/{project_id}/sources/{source_id}/versions. Across Projects: GET /graph/bindings (listBindingsAll). Every operation carries x-nexus-pep naming the action it is decided by. Try them on Graph API › Sources.
