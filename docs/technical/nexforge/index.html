NexForge

NexForge — a scene, not a drawing

How the Forge module keeps one structured Scene behind four views, compiles every hand — pointer, sentence, voice, agent — into the same closed operations with inverses and versions, lets an agent propose but never apply, treats voice as dictation or command, and records every choice.

The NexForge chapters show the module from the outside. This page is the inside. NexForge is apps/forge over forge-api and the nexus_forge database, installed per organization as a pack (Modules). ADR-0056 fixes the object and the engine, ADR-0057 the turn pipeline and the agent. The sentence that organises both: AI proposes, the person applies.

The object

A Scene (nexus://forge/scene/<id>) belongs to a NexChat Project and carries one SceneSpec 1.0: a coordinate system (unit px|m|cm, up_axis z), layers[], objects[], relations[], groups[], cameras[], views, a color_key, bindings[] and tracks[]. A SceneObject has a kind (sticky · text · shape · image · frame · node), a shape, a real transform (position {x, y, z}, rotation_deg) and geometry (width, depth, height, a primitive box · cylinder · wedge · plane), a style (eight hues or none, tint/solid/outline, thin/thick/dashed — colour is scene data) and a semantic.type from twenty-six closed types. Relations have nine kinds; bindings seven (work_item · flow · artifact · claim · dataset · agent · map_feature) and are references only. A view is a projection of this one spec: switching views is not an operation and the version does not move. The 3D view says Conceptual on screen and in every export.

One edit language

Every hand — pointer, keyboard, touch, typed sentence, voice, agent, import — produces SceneOps (forge-scene-op.schema.json): {op_id, kind, target_ids[], payload, source} with source ∈ manual · keyboard · touch · typed · voice · agent · import · system and 26 kinds (add · update · move · resize · transform · set_style · set_color_key · connect · disconnect · group · ungroup · set_layer · set_visibility · set_lock · set_semantic · set_property · bind · unbind · set_camera · add_track_step · delete · restore · layout · reorder · undo · redo). No op carries an utterance or a prompt.

The engine (scenes/engine.py, pure apply_batch(spec, ops, limits)):

  • validates every op (payload, target exists, nothing locked, max_objects 5 000, ops_per_batch 500) and applies all or nothing — OpsRejected lists every reason;
  • computes a per-op inverse from the pre-state and stores it; undo/redo replay the actor's own batches (depth 100);
  • makes one batch one immutable SceneVersion (JSON spec + sha256); restore {n} is a new version equal to n — history is append-only;
  • refuses a batch whose base_version ≠ current with 409 SCENE_VERSION_CONFLICT {current_version, since_ops[]}; (scene_id, request_id) replays return the original result;
  • publish marks a version for the (future) graph projection.

Confirmation levels (packs/nexus-forge/policies/forge-confirmation.json; a Blueprint may only raise): 1 — move, resize, transform, style, colour key, layer, visibility, lock, camera, undo, redo, reorder apply at once with an Undo line; 2 — add, update, connect, group, semantic, property, track step, layout show a card; 3 — delete, ungroup, disconnect, bind, unbind, restore show the exact change; 4 — convert, publish, export, import are doors, never completed by words.

The turn

POST /scenes/{id}/turns is one multipart door: audio or text, a SceneContextSnapshot (active_view, selection_ids, pointer_target, viewport, visible_ids, language, captured_at), request_id, lang, optional proposal_id and dictate. Order: module gate → PEP forge.scene.edit → rate limit (turn_rpm 30) → snapshot version check (SNAPSHOT_STALE) → [audio] transcription through core-api's Gateway → grammar first (deterministic en/uk; a parse with a unique referent needs no model) → deixis (selection > pointer > name; a tie is a choice, never a guess) → the Scene Agent → a SceneProposal. The SSE stream yields transcript first (text, language, confidence — never persisted), then one of proposal | choice | applied | answer | navigate | decline.

The Scene Agent (nexus://agent/agt_forge_scene) applies the skill skl_forge_scene_edit whose output_schema is the proposal contract, holds read tools only (forge.scene.read · knowledge.search · graph.query), is not routable and has no side effects. It is hosted inside forge-api on nexus_agent_runtime.AgentRuntime with the core_api_model_port driver — models only through POST /synapse/inference/complete; refusals cross as typed PortError, never provider text. Its prompt is prompts/scene_turn.md. A proposal has candidates[] {ops, summary, probability} summing to 1, an optional needs_clarification {question_key, options ≤ 5}, a 30-minute TTL, and is re-validated against the current version on apply (stale → 409).

Voice: dictation is not a command

Voice rides the suite’s voice rails (Voice and screen context) with one addition: the snapshot is frozen at mic-open, so a spoken command refers to what the person saw when they started. If an input or textarea outside the composer had focus at mic-open, the mic shows a T glyph and the transcript is inserted into the field with dictate=true — transcript only, no turn. grammar.correction() keeps the last clause after no / no wait / actually / scratch that / ні / тобто…; is_affirmation() applies only the proposal_id on screen (409 PROPOSAL_SUPERSEDED | EXPIRED otherwise); is_negation() cancels it. Clips are ≤ 2 MB and ≤ 30 s, webm/ogg/mp4/wav/mpeg/flac, never stored (transient://). Voice adds no rights: the turn and the apply are the same forge.scene.edit, and the Gateway re-decides model eligibility for the person's actor context. The corpus (tests/voice/corpus/{en,uk}.yaml) passes 33/33 and 28/28.

Who may do what

Three doors in order (Modules). ForgePepAction (10): forge.scene.read · create · edit · delete · export · publish_version · convert · forge.template.manage · forge.present · forge.decision.read; human-only: delete, export, convert, publish. Relations are the Project's: forge.admin (owner) ⊃ forge.edit (editor) ⊃ forge.view (viewer, agent_member). An Organization Admin without a relation gets NO_PROJECT_RELATION; a foreign scene 404. RLS is forced on every table. svc_forge_api holds session.verify · blueprint.read · pep.check · model.invoke (the last one added most recently, awaiting acknowledgement).

Decision data

Eight ForgeDecisionKinds, three of them on every turn: scene_intent (features zoom, level, op_kind, language, active_view, grammar_hit, input_source, pointer_kind, visible_count, candidate_count, selection_count; the full action space; propensity; state_ref = nexus://forge/snapshot/…), voice_transcript_pick (language, media type, duration, confidence, candidates, model id — never the words), deictic_resolution. Outcomes are written by apply, cancel, modify, choose, undo and TTL. Every editor can read the record behind Why this?; decision_outcomes refuses llm_proposed by CHECK.

API and tables

/api/v1/forge: GET/POST /scenes · GET/PATCH/DELETE /scenes/{id} · GET …/objects · POST …/ops · GET …/versions, …/versions/{n}, …/versions/{a}/diff/{b} · POST …/versions/{n}/restore | publish · POST …/turns (multipart → SSE) · GET …/proposals · POST …/proposals/{pid}/apply | cancel | choose · GET/POST /templates, DELETE /templates/{id} · GET /decisions/{id} · GET /health (voice_available). Not yet: /bindings/live, /convert/preview, /convert, /export, /import, /events, /presence, /forge/internal/tools/* (S3–S6). No OpenAPI file is committed; FastAPI /docs on :3209. Tables (Alembic 0001, (tenant_id, id), RLS FORCE): scenes · scene_versions · scene_ops · scene_batches · scene_proposals · scene_templates · decision_records · decision_outcomes · audit_records · outbox.

Deployment and OSS

Web :3219 (BFF /api/forge/*), API :3209, database nexus_forge; profile forge in deploy/contract.yaml, Compose and Helm (forge.enabled off; NetworkPolicy egress postgres · core-api · chat-api). Env: TRANSCRIBER_DRIVER core_api|fixture|none, AGENT_DRIVER core_api|none|scripted, FORGE_DEMO_WORLD (refused in production). Voice needs the asr-local sidecar behind the Gateway — 18–31 s per clip on a laptop CPU today. Nothing OSS is imported yet: SceneCanvas and Scene3D are dependency-free SVG; approved for later slices are LikeC4 @likec4/* (MIT) for the Diagram view, dagre + d3-force for layout, three.js in principle if the SVG spike fails; tldraw and elkjs were rejected, Yjs deferred.

What is built and what is not

Approved: C0 — library, the one door in, five templates, Board with palette and handles, the element bar, Inspector, four views, versions and restore, typed turns with grammar + agent, the 409 conflict card. Built, awaiting the owner's microphone walk: S2 voice. Not yet: the LikeC4 Diagram renderer (the current Layered layout is a stand-in), conversions and live bindings (S4), exports/imports over the API, presence, graph projection, images, own templates over the live API, spoken read-backs, the Voice Dock hand-off.
